# 开发协作说明

## 当前状态

仓库目前仅有协作骨架。后端、前端、数据库连接、模型调用、WorkBuddy 接入和三个业务流程均待实现；尚无经过验证的启动命令或部署流程。

确定的技术栈为 Java + Spring、Next.js + React、MongoDB、Apifox、Git、Docker。具体版本、依赖锁文件与可运行配置属于后续工作。

## 分工

| 负责人 | 范围 |
| --- | --- |
| A | 后端公共接口、统一任务机制、立项材料审查、模型接入 |
| B | 前端页面、接口联调、协助 Excel 拆表 |
| 共同 | 立项书起草、部署配置、业务验收 |

两人可分别使用个人 GPT 账号辅助开发。需求决策、接口变更和实现结果应同步到仓库或 Apifox，不能只留在个人对话中。

## 协作流程

1. 在 `docs/` 写清本次需求、输入输出及验收条件。
2. 在 Apifox 先确认接口契约，包括字段、任务状态、错误处理和文件约束；将不含敏感信息的导出文件纳入 `apifox/`。
3. 从最新 `main` 建立 `feature/...` 分支，例如 `feature/review-api` 或 `feature/review-page`。
4. 按已确认契约实现功能；契约变化须先同步另一位协作者并更新文档。
5. 提交前检查差异并完成与改动相符的验证，再发起 Pull Request，由另一位协作者审阅后合并。

后端统一承接三个业务的任务处理；WorkBuddy 作为调用入口。各模块的契约与职责应保持一致，具体实现另行设计。

## 文件归属与数据约束

- `backend/`、`frontend/`：业务代码。
- `deploy/`、`config/`：部署配置与不含密钥的配置模板。
- `apifox/`、`docs/`：接口契约、需求及开发记录。
- `templates/`、`tests/`：经确认可提交的模板、测试代码及脱敏样例。

原始客户文件、未经脱敏的业务材料、生成输出、真实密钥和本地敏感配置不入库。测试优先使用合成或脱敏数据；配置模板仅填写占位值。提交前仍须检查暂存内容，不能仅依赖 `.gitignore`。

## 后续环境工作

- 固定 Java、Spring、Node.js、Next.js、React、MongoDB 及相关依赖的版本，记录兼容要求。
- 确定后端构建工具与前端包管理器，补齐相应的版本固定配置及依赖锁文件。
- 补齐 Docker 镜像、编排与本地配置示例，明确数据持久化和模型服务配置方式。
- 完成实际启动及端到端验证后，再写入可复现的启动、部署和验收步骤。

这些事项尚未完成；使用 Docker 和固定版本是约定的实现方向，不表示当前仓库已经具备可运行环境。
